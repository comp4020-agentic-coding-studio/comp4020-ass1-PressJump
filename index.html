Eight agents, one repo

Pointing N coding agents at one repository doesn't buy you N× the speed — they all want the same working directory. And the obvious fix, a worktree each, quietly isn't enough either. The missing half is a shared build cache, and this page lets you discover why.

Skip to the simulator ↓

Every agent runs the same loop

Each simulated agent works through three tasks, and every task has the same shape: plan → edit → build → test. Two of those steps are greedier than they look. Editing and testing need the working tree — the actual files on disk — and no two agents can safely hold it at once. Building needs a CPU core, a build output, and, crucially, a warm cache: the first build after a cache goes cold pays a heavy penalty to recompile the world.

On every timeline below, real work is coloured, wasted work is hatched red, and waiting is a dotted line.

Setup 1 — one shared checkout

The default is invisible: everyone works in the same checkout. The agents don't crash into each other — they queue. Each handover is a branch switch that costs a little time and, far worse, dirties the build cache, so almost every build runs cold. Adding an agent adds no throughput at all; it adds a place in the queue, and the wall clock grows with every agent you add.

Setup 2 — a worktree each

The fix everyone reaches for: git worktree add, one checkout per agent. The queue disappears — and yet every worktree starts empty, so every agent pays the cold build that the shared checkout at least occasionally avoided. It's much faster, but look at the heat: all that hatched red is the same world being recompiled once per agent, and past your core count it starts landing back on the wall clock.

Setup 3 — worktrees plus a shared build cache

The half nobody talks about: keep the isolation, share the cache (ccache, sccache, Bazel, Turborepo — pick your ecosystem's). Now exactly one build in the whole system runs cold, and it warms the cache for everyone; the rest do only their own incremental work. At four agents the wall clock merely ties setup 2 — the win hides in the missing red. Crank the agent count in the lab and watch the gap open.

The takeaway

Isolation removes the queue. The shared cache removes the cold tax. You need both, and almost every "run more agents" setup ships with only the first — or with neither.

The deeper habit this page is arguing for: when parallelism disappoints, go looking for the resource nobody wrote down. Here it was the working directory and the build cache; in your system it will be something else with the same shape.

All durations are abstract time units — deliberately unmeasured placeholders, each marked TODO(measure) in src/model.ts. The claim is the shape of the story, not the seconds. The scheduler is deterministic and property-tested: busy time is provably identical across all three setups; only wasted and blocked time differ.

A static, client-side simulation. No servers, no tracking, no network — the source repository holds the model and the property tests that gate it.
